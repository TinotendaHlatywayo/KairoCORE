## 1. Overview & Objectives

This document outlines the consolidated Billing & Subscriptions workflow for Kairo CORE following the elimination of duplicate subsystems, dead code paths, and racy confirmation logic.

### Core Architecture
- **Single Source of Truth for Subscriptions:** `Modules\SaaS\Models\SaaSSubscription` (`saas_subscriptions` table).
- **Single Source of Truth for Verification & Credit:** `Modules\SaaS\Services\SubscriptionManager::processTransactionVerification()` (guarded for idempotency against multi-confirmation races from webhooks, polls, sandbox completions, and manual approvals).
- **Single Source of Truth for Messaging:** `Modules\SaaS\Services\PlatformMessagingService` (all automated billing notifications now delegate to this service rather than hand-rolling duplicate message/recipient records).
- **Single Source of Truth for Settings:** 
  - `PlatformBillingSetting` (offsets, dunning schedules, super-admin alert toggles).
  - `SaaSBillingSetting` (Paynow credentials and gateway configuration).

## 2. Subscription Lifecycle & Automated Workflows

### 2.1 Daily Billing Scheduler (`saas:run-billing-notifications`)
- Scheduled via `routes/console.php` (`dailyAt('07:00')`).
- Executes `BillingNotificationService::run()`, which iterates over all active/grace-period subscriptions.
- **Offset Calculation (`applicableTemplateKeys`):**
  - Evaluates signed day distance (`offset`) between today and the tenant's recurring billing date.
  - Safely accumulates templates into an offset map (preventing key collisions when reminder windows overlap).
  - Emits reminders (`billing_reminder`, `billing_day_before`, `billing_due_today`, `billing_overdue`, `billing_suspension_warning`, `billing_suspended`).
  - **Deduplication:** A unique database index on `(school_id, template_key, billing_date)` (`PlatformBillingNotificationLog`) guarantees that each notice fires exactly once per billing cycle, even if the scheduler runs repeatedly.

### 2.2 Payment & Confirmation Pipeline
1. **Initiation:** Tenants initiate payments via `SaaSBillingOverview` (`/workspace/saa-s-billing-overview`), which initializes a Paynow transaction and registers a pending `SaaSTransaction`.
2. **Gateway Return / Webhook / Sandbox / Manual Approval:**
   - **Paynow Webhook:** `PaynowWebhookController` receives gateway notification, matches on the transaction reference, and marks complete.
   - **Manual Bank Deposit:** Super-admins approve deposits via `PendingPaymentResource` (`/platform/pending-payments`), creating a completed transaction record.
3. **Execution (`SubscriptionManager::processTransactionVerification`):**
   - **Idempotency Guard:** An early-return check and row lock ensure that if a transaction has already been verified (e.g. webhook and poll arriving concurrently), subsequent calls return the existing receipt instantly without duplicating receipts, accounting expenses, or emails.
   - **Ledger & Lifecycle Updates:** Sets transaction status to `completed`, marks the invoice `paid` and locked, advances subscription `next_payment_date` and `ends_at`, generates an official numbered SaaS receipt (`REC-SAAS-...`), emails `SaaSReceiptMail`, and posts an automated expense record into the tenant's local finance ledger.

## 3. Consolidated Notification & Messaging Workflow

- Automated billing reminders and dunning notices are generated by `BillingNotificationService` and dispatched via `PlatformMessagingService::sendFromPlatform()`.
- This ensures all notices appear in both the platform audit logs and the tenant inboxes (`PlatformMessage` / `PlatformMessageRecipient`), with automated chunked database notifications (`PlatformMessageNotification`) and optional email delivery.

---

## 4. Timezone & Platform Notification Center

- **Platform Timezone:** Configured via `APP_TIMEZONE` (defaulting to `Africa/Harare`) in `config/app.php`, aligning platform server timestamps and wall-clock time with local operational hours.
- **Platform Notification Center:** Added a dedicated Livewire component (`PlatformCommandCenter`) in the platform topbar (`TOPBAR_END`), mirroring the design language of the school workspace command center with a live-updating date/time badge, unread counter, dropdown notification feed, mark-read actions, and 30-day history.
